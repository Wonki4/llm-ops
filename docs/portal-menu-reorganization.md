## 최종 메뉴와 기존 주소 대응

가이드·공지사항·모델 캘린더·모델 대시보드·내 팀·팀 탐색·내 전체 키·내 요청은
상단에 그룹 제목 없이 유지한다. 첫 진입은 기존대로 내 팀이다.

| 그룹 | 메뉴 | 주소와 탭 | 기존 화면의 이동 |
|---|---|---|---|
| 서빙 | 운영 현황 | `/admin/serving` | 기존 서빙 홈 유지 |
| | 배포 | `/admin/deployments`, `/admin/llmd` | 서빙 디플로이먼트 / 라우터·llm-d |
| | 레시피 | `/admin/recipes` | 기존 제공자 → 모델 → 레시피 유지 |
| | 검증·벤치마크 | `/admin/benchmarks/validations`, `/admin/benchmarks` | 레시피 검증 / 측정 실행 |
| | 인프라 | `/admin/infrastructure?tab=clusters|storages|gpu|pods` | 클러스터·ArgoCD / 스토리지 / GPU 프로필 / Pod 기본 설정 |
| 모델 관리 | 모델 등록·카탈로그 | `/admin/models` | 대시보드 요약·등록·카탈로그 |
| | 라우팅 그래프 | `/admin/serving/topology` | 기존 그래프와 클러스터 범위 재사용 |
| | 상태·일정 | `/admin/models/history?tab=schedule|history` | 공개·종료 일정 / 상태 변경 이력 |
| 팀·사용자 관리 | 팀 | `/admin/teams`, `/admin/teams/{id}` | 목록에서 팀별 숨김 전환; 상세는 멤버 / 모델 호출 권한 / 서빙 권한 / 예산·한도 / 사용량 / 설정 |
| | 사용자 | `/admin/users/{id}?tab=teams|personal|keys` | 소속 팀 / 개인 모델 권한 / API 키 |
| | 모델 접근 그룹 | `/admin/access-groups?group={name}&tab=models|teams|users` | 모델 / 할당된 팀 / 할당된 사용자 |
| | 요청 관리 | `/admin/requests?type=join|budget` | 팀 가입 / 예산 변경, 별도 상태 필터 |
| | 예산·사용량 | `/admin/finance?tab=budget|usage` | 기존 예산·사용량 폼과 표·캘린더 재사용 |
| | 기본 할당 정책 | `/admin/policies?tab=teams|keys` | 신규 사용자·팀 정책 / API 키 기본값 |

관리자 모델 상세의 기준 주소는 `/admin/models/detail/{호출명}`이다. `connections`, `catalog`,
`pricing`, `assignments` 탭으로 연결 / 카탈로그 / 요금 / 할당 현황을 표시한다.
`history` 같은 호출명은 시스템 경로와 충돌하지 않으며 `/`가 있는 호출명도 지원한다.
기존 `/admin/models/{호출명}` 주소는 새 상세로 연결한다.

이전 `/admin/models/dashboard`, `/admin/storages`, `/admin/budgets`, `/admin/usage`는 각각 모델 목록,
인프라 스토리지, 예산 탭, 사용량 탭으로 연결한다. `/admin/settings`의 기존 탭은 해당 인프라·정책
탭으로, 팀을 지정한 서빙 권한 링크는 관리자 팀 상세로 이동한다. 기존 개별 상세 URL은 유지한다.
클러스터·네임스페이스·팀 쿼리와 새 탭 선택은 새로고침·뒤로가기에서 복원한다.

## 권한과 데이터 경계

- 일반 사용자는 상단 8개 메뉴를 본다. 팀 관리자는 요청 관리와 담당 팀의 멤버·설정을 관리한다.
- 네임스페이스 서빙 조회자·운영자는 운영 현황에서 허용 범위로 진입한다. 운영자의 레시피 배포와
  관리 동작에는 기존 API의 서빙 권한 검사를 그대로 적용한다. 팀 관리자 역할만으로 서빙 권한을 주지 않는다.
- 포털 관리자만 전체 메뉴와 신규 연결·팀 할당 API를 사용한다. UI 노출 여부와 별개로 API도 권한을 검사한다.
- 내 팀과 관리자 팀 상세는 멤버·사용량·설정 컴포넌트를 공유한다. 관리자 예산 탭과 일반 설정 탭은
  해당 영역의 설정만 저장하여 다른 탭 값을 덮어쓰지 않는다.
- LiteLLM 연결·권한·기본 단가는 LiteLLM에서 읽는다. 통합 모델 목록은 호출명으로 묶고 연결 ID를
  모두 표시한다. 기본 단가는 읽기 전용이며 시간대 요금은 기존 컴포넌트를 사용한다.
- 팀의 빈 허용 목록은 LiteLLM에서 전체 허용이므로 차단 저장에는 `no-default-models`를 사용한다.
  직접 할당·모델 접근 그룹·상속 그룹을 구분하며 상속 권한이 남으면 실효 권한에 표시한다.
- 외부 연결 등록은 요청 키로 재시도를 구분한다. 수정 시 입력하지 않은 자격 증명을 보존하고 응답에
  공급자 자격 증명을 포함하지 않는다. 설정 파일 연결은 읽기 전용이다. 연결 삭제는 해당 ID만 대상으로 하며
  Kubernetes 리소스나 같은 호출명의 다른 연결을 삭제하지 않는다.

## 최초 통합 검증 (2026-11-22, 캐시 카탈로그 삭제 전)

### 자동 검사

- TypeScript 검사 및 Next.js 프로덕션 빌드 통과.
- 메뉴·역할·기존 주소·비기본 클러스터 기본 네임스페이스 테스트 7개 통과.
- 변경 영역의 백엔드 테스트 88개 통과: 모델 등록/카탈로그/연결, 관리자 팀,
  접근 그룹, 개인 권한, 상속 그룹, 팀 설정, 라우팅 그래프.
- 전체 백엔드 실행: 1,308 통과, 9 건너뜀, 19 실패, 11 오류. 동일한 실패 파일을 변경 전
  기준 코드에서도 실행해 같은 30건을 재현했다. 기본 DB·서버 의존 및 기존 fixture 문제이며
  이번 변경으로 새로 실패한 테스트는 없었다. 전체 테스트가 모두 통과했다는 의미는 아니다.
- 별도 안정화 #290: 레시피 검증·prefix·manifest 관련 56개 테스트 통과.

### 실제 LiteLLM 연계

격리된 PostgreSQL 16, Redis 7, LiteLLM v1.103.0과 포털 API를 실행했다. 인증은 로컬 테스트 사용자로
대체했으며 역할별 API 검사 자체는 실제 코드를 사용했다. 추론 제공자는 Authorization을 검사하는
OpenAI 호환 mock 서버다. 운영 DB·클러스터·키는 사용하지 않았다.

1. 외부 모델 연결 등록과 같은 요청 키 재시도에서 중복이 생기지 않음.
2. 같은 호출명의 두 연결이 목록과 상세에 표시되고, 한 연결 수정·삭제 후 다른 연결 보존.
3. 수정 시 빈 API 키를 보내도 기존 자격 증명이 유지되어 실제 프록시 요청 성공.
4. 카탈로그 등록 후 모델 접근 그룹을 B팀에 할당. 실제 LiteLLM 호출 **B팀 200 / C팀 403**.
5. B팀 할당 회수 후 이미 발급된 같은 B팀 키의 호출 **403**. 재할당 후 복원.
6. LiteLLM에서 직접 바꾼 단가와 팀 권한이 포털 조회에 반영됨.
7. 일반 사용자·팀 관리자의 전역 팀/연결 관리 API 접근 **403**.
8. 격리 DB의 기존 Alembic 마이그레이션을 065까지 적용 완료.
9. 팀 탐색 → 가입 신청 → 승인 → 내 팀 반영 → 포털 팀 키 발급 → 실제 LiteLLM 호출 200.
10. 개인 키 정책 활성화 → 개인 모델 권한 부여 → 포털 개인 키 발급 → 실제 LiteLLM 호출 200.

## 후속 변경: Redis 캐시 카탈로그 제거

모델 목록의 공통 캐시 설정과 모델 상세의 캐시 탭, 모델 상세 시트의 캐시 링크를 제거했다.
`/admin/catalog`은 모델 등록·카탈로그로 이동하고 기존 `?tab=cache` 링크는 연결 탭으로 표시한다.
캐시 카탈로그 전용 API(`/api/catalog`, 모델별 `/cache`), Redis 클라이언트·패키지 의존성,
백엔드 `APP_REDIS_*` 설정과 관련 번역·훅도 제거했다.

일반 모델 카탈로그, LiteLLM 연결·가격, 시간대 요금, 벤치마크 prefix 캐시 기능은 유지한다.
이 변경은 기존 Redis 데이터나 DB의 과거 설정·테이블을 삭제하지 않으며 새 마이그레이션이 없다.

삭제 후 검증: 모델 카탈로그·연결·시간대 요금·prefix 캐시·설정/health 테스트 59개와 메뉴 테스트
7개, TypeScript·프로덕션 빌드 통과. 로컬 Redis 중지 상태에서 모델·연결·요금 조회가 200,
제거한 카탈로그·모델 캐시 API는 404임을 확인했다.

## 후속 변경: 팀 메뉴에서 숨김 관리

팀 목록 각 행에서 숨김을 켜고 끈다. 켜면 기본은 팀 탐색에서만 숨기며, 범위 선택으로
소속 멤버의 내 팀·키 목록에서도 숨길 수 있다. 기본 할당 정책의 중복 숨김 편집 화면은 제거했다.
모델·접근 그룹 상세에 포함된 팀 목록에는 전역 표시 설정을 노출하지 않는다.

기존 숨김 설정을 그대로 사용하고, 새 팀별 PATCH API는 대상 팀만 추가·제거한다.
서로 다른 팀을 동시에 변경해도 다른 팀의 설정을 덮어쓰지 않는다. 기존 전체 변경 API와
포털 관리자 권한 검사는 유지한다. DB 마이그레이션은 없다.

검증: 숨김·관리자 팀·개인 키 정책·설정 테스트 22개, TypeScript·ESLint·프로덕션 빌드 통과.
격리된 실제 PostgreSQL에서 동시 팀 변경 시 다른 팀 설정 보존, 두 모드의 팀 탐색·내 팀·키 목록 반영,
숨김 해제, 관리자의 전체 조회와 일반 사용자 변경 거절을 확인했다.
